# NexiLink Downloader Telegram Bot

ربات دانلود همه‌کاره تلگرام، نوشته‌شده با **Python 3.11**، **Telethon** و **yt-dlp**، آماده اجرا روی **Railway** با **Docker**.

این نسخه از پروژه، پس از یک بازبینی کامل کد، اصلاح باگ‌های پلتفرم‌ها و اضافه‌شدن پنل مدیریت پیشرفته برای ربات مدیر (Manager Bot) ارائه می‌شود.

---

## ۱. ساختار پروژه

```
├── main.py                  # نقطهٔ ورود برنامه؛ راه‌اندازی ربات اصلی + ربات مدیر
├── config.py                 # تمام تنظیمات از طریق Environment Variables
├── database.py                # لایهٔ SQLite (aiosqlite) - کاربران، دانلودها، تنظیمات، Broadcast
├── admin_settings.py          # ⭐ جدید: مدیریت محدودیت‌ها و پیام‌های قابل‌ویرایش ادمین
├── handlers.py                 # منطق اصلی مکالمه، مسیر‌دهی پلتفرم‌ها، دانلود/آپلود
├── manager_bot.py               # ⭐ به‌روزرسانی‌شده: ربات مدیر با امکانات جدید
├── messages.py                   # تمام متن‌های کاربر (فارسی) + سیستم Override پیام‌ها
├── platforms_registry.py          # لیست پلتفرم‌های پشتیبانی‌شده و مسیر‌دهی لینک‌ها
├── downloader.py                    # موتور دانلود عمومی مبتنی بر yt-dlp (یوتیوب، تیک‌تاک و ...)
├── pinterest_service.py               # دانلود پین‌ترست (عکس / ویدیوی واقعی / کاروسل)
├── instagram_service.py                # دانلود اینستاگرام (عکس / ریلز / کاروسل)
├── twitter_service.py                   # دانلود ایکس/توییتر (عکس، چند‌عکسی، ویدیو، گیف)
├── soundcloud_service.py                 # دانلود ساندکلاود (تک‌آهنگ و پلی‌لیست)
├── pornhub_service.py                     # منطق اختصاصی PornHub (پیام‌ها قابل‌ویرایش)
├── inline_mode.py                          # حالت Inline تلگرام
├── cooldown.py                              # سیستم Cooldown کاربران
├── concurrency.py                            # محدودیت دانلود هم‌زمان (Semaphore)
├── event_logger.py                            # صف رویداد بین ربات اصلی و ربات مدیر
├── fast_upload.py                              # آپلود موازی/سریع فایل به تلگرام
├── media_attrs.py                               # تشخیص ابعاد/مدت‌زمان واقعی رسانه (ffprobe)
├── utils.py                                      # توابع کمکی (نام‌گذاری فایل، فرمت، ZIP، اعتبارسنجی URL)
├── telegram_client.py                             # ساخت کلاینت Telethon (ربات اصلی/مدیر)
├── generate_session.py                             # ابزار کمکی تولید Session (اختیاری)
├── Dockerfile
├── requirements.txt
└── .env.example
```

> نکته: در بازبینی کامل، مشخص شد سرویس‌های Pinterest، Instagram و Twitter/X در نسخهٔ فعلی مخزن **از قبل اصلاح شده بودند** (تشخیص واقعی استریم ویدیو، رفع خطای `_TITLE_RE`، استفاده از FixTweet برای عکس‌های توییتر و ...). این بازبینی، صحت آن‌ها را تأیید کرد و تمرکز اصلی تغییرات روی نقاطی بود که واقعاً ناقص بودند: **پنل مدیریت محدودیت‌ها و پیام‌های سفارشی در ربات مدیر** (بخش‌های A و B مورد ۷) که فایل `admin_settings.py` و به‌روزرسانی `manager_bot.py` / `main.py` آن را کامل می‌کند.

| 7 | ربات مدیر امکانات محدودی داشت | ✅ **جدید**: `admin_settings.py` + دستورات `/limits` و `/messages` در `manager_bot.py` |

## ۳. متغیرهای محیطی (Environment Variables)

فایل `.env.example` را به `.env` کپی کنید (یا در Railway → Variables وارد کنید):

| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `API_ID`, `API_HASH` | از my.telegram.org | - |
| `BOT_TOKEN` | توکن ربات اصلی از BotFather | - |
| `MANAGER_BOT_TOKEN` | توکن ربات مدیر (دومین ربات، از BotFather) | - |
| `OWNER_ID` | آیدی عددی مالک ربات | - |
| `MANAGER_ADMIN_IDS` | آیدی‌های عددی ادمین‌های اضافه (با کاما جدا) | خالی |
| `MANAGER_CHAT_ID` | چتی که گزارش‌ها ارسال می‌شود | = OWNER_ID |
| `MAX_FILE_SIZE` | حداکثر حجم فایل (بایت) | 2GB |
| `MAX_CONCURRENT_DOWNLOADS` | حداکثر دانلود هم‌زمان | 2 |
| `COOLDOWN_ENABLED` / `COOLDOWN_COUNT` / `COOLDOWN_SECONDS` | تنظیمات اولیهٔ Cooldown (بعداً از ربات مدیر هم قابل تغییر) | false / 5 / 60 |
| `ZIP_THRESHOLD_ITEMS` | آستانهٔ پیشنهاد ZIP برای کاروسل‌ها | 6 |
| `MAX_PLAYLIST_TRACKS` | حداکثر تعداد ترک قابل پردازش در پلی‌لیست ساندکلاود | 100 |
| `PORNHUB_ENABLED` / `PORNHUB_NOTIFY_ADMIN` | فعال/غیرفعال‌سازی PornHub و اطلاع‌رسانی به مالک | true / true |
| `PINTEREST_ENABLED` / `INSTAGRAM_ENABLED` / `TWITTER_ENABLED` | فعال/غیرفعال‌سازی هر پلتفرم | true |
| `INSTAGRAM_COOKIES` | کوکی Netscape برای پست‌های خصوصی/محدود (اختیاری) | خالی |
| `INLINE_MODE_ENABLED` | فعال‌سازی حالت Inline | true |
| `DOWNLOAD_PATH` | مسیر دانلود موقت | `/tmp/downloads` |
| `DB_PATH` | مسیر فایل SQLite | `bot_data.db` |
| `LOG_LEVEL` | سطح لاگ | INFO |

> ⚠️ **مهم:** برای این‌که Inline Mode و منوی دستورات کار کند، ربات اصلی باید فقط با `BOT_TOKEN` بالا بیاید، نه با یک Session کاربر شخصی. این پروژه از قبل به این صورت پیاده‌سازی شده است.

## ۴. دیپلوی روی Railway

1. ریپازیتوری را در Railway به‌عنوان یک پروژه جدید (Deploy from GitHub Repo) وصل کنید.
2. Railway به‌صورت خودکار `Dockerfile` را تشخیص و بیلد می‌کند.
3. در بخش **Variables**، تمام متغیرهای بالا را وارد کنید (حداقل `API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_ID`).
4. اگر می‌خواهید ربات مدیر هم اجرا شود، `MANAGER_BOT_TOKEN` را هم اضافه کنید (هر دو ربات در یک container و یک process اجرا می‌شوند، نیازی به Service جدا نیست).
5. برای حفظ دیتابیس SQLite بین دیپلوی‌ها، یک **Volume** به مسیر پروژه وصل کنید و `DB_PATH` را روی مسیر آن Volume تنظیم کنید (مثلاً `/data/bot_data.db`).
6. Deploy را بزنید؛ لاگ‌ها باید پیام `NexiLink is up and running.` را نشان دهند.

## ۵. فعال‌سازی حالت Inline (مرحله به مرحله)

کد سمت پایتون (`inline_mode.py`) کامل است، اما تلگرام برای فعال‌شدن Inline Mode نیاز به تنظیمات دستی در **BotFather** دارد:

1. به [@BotFather](https://t.me/BotFather) پیام دهید.
2. دستور `/mybots` را بزنید و ربات اصلی خود را انتخاب کنید.
3. `Bot Settings` → `Inline Mode` → `Turn on` را انتخاب کنید (یا مستقیماً دستور `/setinline` را بزنید).
4. وقتی BotFather یک **Placeholder** خواست (متنی که قبل از تایپ لینک به کاربر نشان داده می‌شود)، مثلاً بنویسید:
   ```
   یک لینک برای دانلود بفرست...
   ```
5. (اختیاری ولی توصیه‌شده) `/setinlinefeedback` → `Enabled` را بزنید تا callback دکمه‌های نتیجهٔ Inline به‌درستی به سرور شما گزارش شود.
6. مطمئن شوید `INLINE_MODE_ENABLED=true` در Environment Variables تنظیم شده و ربات با `BOT_TOKEN` (نه Session کاربر) اجرا می‌شود.
7. ربات را ری‌استارت/دیپلوی مجدد کنید.
8. تست: در هر چتی تایپ کنید `@نام‌کاربری‌ربات یک لینک یوتیوب`. باید نتیجه با دو دکمهٔ «دانلود ویدیو» / «دانلود صدا» نمایش داده شود.

اگر Inline نتیجه نداد، این موارد را چک کنید:
- Inline Mode واقعاً در BotFather روشن باشد (`/setinline`).
- ربات یک **Bot Account** واقعی باشد (نه Session کاربر).
- در Railway، لاگ‌ها خطای Timeout در `handle_inline_query` نشان ندهند (شبکه یا استخراج اطلاعات کند نباشد).

## ۶. راه‌اندازی ربات مدیر (Manager Bot)

1. یک ربات جدید در BotFather بسازید (`/newbot`) و توکن آن را در `MANAGER_BOT_TOKEN` قرار دهید.
2. `OWNER_ID` را روی آیدی عددی تلگرام خودتان تنظیم کنید (با ربات‌هایی مثل @userinfobot می‌توانید آیدی خود را پیدا کنید).
3. در صورت نیاز، ادمین‌های اضافه را در `MANAGER_ADMIN_IDS` (با کاما جدا) اضافه کنید.
4. پس از دیپلوی، به ربات مدیر پیام `/start` بدهید تا منوی دستورات را ببینید.

### دستورات ربات مدیر

| دستور | توضیح |
|---|---|
| `/stats` | آمار کلی (کاربران، دانلود موفق/ناموفق) |
| `/logs` | آخرین رویدادهای دانلود |
| `/interval` | تنظیم بازهٔ ارسال گزارش‌های تجمیعی |
| `/limits` | ⭐ تنظیم محدودیت‌ها: حداکثر حجم فایل، حداکثر دانلود هم‌زمان، تعداد دانلود قبل از Cooldown، مدت‌زمان Cooldown (با دکمه‌های Inline، بدون نیاز به ویرایش کد) |
| `/messages` | ⭐ ویرایش پیام‌های قابل‌تنظیم ربات (پیام‌های PornHub، خوش‌آمدگویی، خطا، موفقیت، Cooldown و ...) — روی دکمهٔ پیام مورد نظر بزنید، سپس «✏️ Edit» و متن جدید را ارسال کنید؛ تغییر بلافاصله و بدون ری‌استارت اعمال می‌شود |
| `/broadcast <متن>` | ارسال پیام همگانی به همهٔ کاربران؛ ابتدا تعداد گیرندگان و تأییدیه نشان داده می‌شود، سپس نوار پیشرفت زنده (ارسال‌شده/ناموفق) و گزارش نهایی |
| `/ping` | زمان روشن بودن ربات |

> پیام‌های قابل ویرایش از طریق `/messages` در `messages.CUSTOMIZABLE_KEYS` تعریف شده‌اند و برای اضافه‌کردن کلید جدید فقط کافی است آن را به این لیست و دیکشنری `MESSAGES` اضافه کنید — چیزی در کد Hardcode نشده است.

### کنترل Cooldown با نمایش شمارش معکوس

وقتی کاربری به تعداد `COOLDOWN_COUNT` (قابل تغییر با `/limits`) دانلود موفق داشته باشد، پیام Cooldown برایش ارسال و هر چند ثانیه یک‌بار زمان باقی‌مانده به‌صورت شمارش معکوس ویرایش می‌شود تا کاربر بداند دقیقاً چه زمانی می‌تواند دوباره درخواست بدهد.

## ۷. دستورات ربات اصلی (کاربران)

| دستور | توضیح |
|---|---|
| `/start` | شروع/معرفی ربات |
| `/help` | راهنما |
| `/platforms` | لیست سایت‌های پشتیبانی‌شده |
| `/settings` | نمایش محدودیت‌های فعلی (حجم فایل، Rate limit، دانلود هم‌زمان) |
| `/status` | وضعیت درخواست جاری |
| `/cancel` | لغو عملیات جاری |
| `/about` | دربارهٔ ربات |

### گردش‌کار کاروسل (پین‌ترست / اینستاگرام)

وقتی لینک شامل چند تصویر باشد، ربات می‌پرسد:

> «چطور می‌خوای عکس‌ها رو دریافت کنی؟»
> 1) ارسال جداگانه   2) ارسال به‌صورت ZIP

انتخاب «جداگانه» فایل‌ها را با کیفیت اصلی و ترتیب صحیح ارسال می‌کند؛ انتخاب ZIP یک آرشیو واحد می‌سازد.

### گردش‌کار پلی‌لیست ساندکلاود

1. لینک پلی‌لیست ارسال می‌شود → ربات تعداد ترک‌ها را اعلام می‌کند.
2. سؤال: دریافت به‌صورت **ZIP** یا **فایل‌های جداگانه**؟
3. سؤال: دانلود **همهٔ ترک‌ها** یا **ترک‌های انتخابی**؟
4. در صورت انتخاب گزینهٔ دوم، شماره‌های ترک (هر شماره در یک خط، مثال: `12` `15` `18`) دریافت و اعتبارسنجی می‌شود، سپس فقط همان ترک‌ها با فرمت انتخابی ارسال می‌شوند.

## ۸. نکات فنی / سازگاری Railway و Docker

- تمام دانلودها در `DOWNLOAD_PATH` (پیش‌فرض `/tmp/downloads`) انجام و پس از ارسال یا خطا با `utils.safe_delete` پاک‌سازی می‌شوند (جلوگیری از پر شدن دیسک Railway).
- تعداد دانلود هم‌زمان با `concurrency.download_semaphore` محدود می‌شود؛ از طریق `/limits` می‌توان این مقدار را در Runtime تغییر داد بدون نیاز به ری‌استارت.
- تمام فراخوانی‌های I/O سنگین (`yt-dlp`, ffprobe) داخل `loop.run_in_executor` اجرا می‌شوند تا event loop اصلی مسدود نشود.
- دیتابیس SQLite (`aiosqlite`) با یک Connection مشترک بین ربات اصلی و ربات مدیر کار می‌کند (هر دو در یک process).
- Dockerfile شامل نصب `ffmpeg` (لازم برای yt-dlp/merge ویدیو و mutagen) است؛ در صورت تغییر Base Image این وابستگی را حفظ کنید.
